# Developer Voice · Rust 社区情感分析平台

面向 GitHub Issue、Pull Request 和评论的方面级情感分析前端。当前采用 `rust-aspects-v2` 的 13 个方面，以及正面、中性、负面三分类。

> 当前默认连接后端 sentiment_facts 查询表；统计数量和情感评分来自查询表。独立的季度主题模块读取服务器 BERTopic 结果；方面详情中的示例关键词、事件解读及单文本推理仍为 mock。生产服务器需按部署说明启动 API 并刷新查询表。

## 页面功能

### 顶部统计卡

依次展示已标注语料量、方面标注量、正向数据量、负面问题量。语料及正负面卡片按 corpus_id 去重；方面标注量为查询表行数。一条语料可能在不同方面同时包含正面和负面标签。

### 时间线

- 自由选择起始、截止年月，包含两端月份，支持单月；倒置的时间范围自动排序。
- 点击整个日期框可打开年月选择器；日期标签位于框外。
- 支持快捷范围、滚轮缩放、拖动浏览及下方范围条。
- 按分析维度展示一条月度情感评分折线，纵轴上方为 `1`，下方为 `-1`，`0` 为中性基准。
- 评分计算：`(positive - negative) / total`，其中 `total = positive + neutral + negative`。中性样本参与分母。
- Rust 事件节点位于对应月份的评分曲线上；点击节点查看事件解读。

### 13 大类情感画像

左侧饼图展示各方面标注量占比，每个扇区用引导线标明分类。右侧雷达图展示各类在选定时间范围的情感评分，使用相同评分公式；中心为 `-1`，中间环为 `0`，外圈为 `1`，轴标签为实际分类名称。

下方统一展示“方面分类、占比与评分”。一条文本可以涉及多个方面，所以分类占比的分母是方面标注次数，与去重语料总量不同。

点击分类名称、饼图扇区或雷达图评分点，可打开详情悬浮窗，展示选定范围内该类总量、正面／中性／负面数量，以及各类关键词。点击窗口外、关闭按钮或按 Escape 关闭。独立的“高频问题关键词”板块已移除。

支持浅色、深色及跟随系统主题，偏好保存在本地浏览器。

### 季度主题探索

新增侧栏“季度主题”，保留原有总览、趋势与方面画像。季度范围跟随顶部月份范围，
选择与范围相交的完整自然季度（UTC），支持季度下拉切换、前后季度、主题关键词搜索。
展示去重语料数、主题数、已归类/未归类数量及占比，主题卡片可以展开真实代表语料并跳转 GitHub 原文。
样本不足、全部未归类、无匹配季度与接口错误分别展示，主题名称直接使用后端保存的中文概括。
各季度独立聚类，主题编号不能直接跨季度比较。新模块始终请求真实接口，不回退至模拟主题。

## 本地运行

需要能运行 Vite 7 的 Node.js 环境。

```bash
npm install
npm run dev
```

浏览器打开终端显示的地址，通常为 `http://localhost:5173/`。端口已占用时，以终端输出为准。在启动服务的终端按 Control+C 停止；已加载的浏览器页面会保留，刷新后才会重新请求服务。

```bash
npm run build
npm run preview
```

构建产物位于 `dist/`。

## 接入后端与 Ubuntu 部署

前端和后端分别位于并列的 Developer-Voice、github-sentiment 目录。
开发阶段通过 SSH 隧道连接服务器后端：配置 `.env.development.local`，
分别运行 `npm run tunnel` 和 `npm run dev`；见 [SSH 开发联调](docs/ssh-development.md)。
生产构建已默认使用 `.env.production` 的真实统计模式。
通过 Nginx 将 `/api/v1` 代理到后端 `127.0.0.1:8000`；Vite 开发服务器也配置了 `/api` 代理。
季度主题通过 `/api/v1/topics` 读取服务器本地结果；方面详情示例关键词、事件和单文本推理仍为 mock。
接口错误不会回退到模拟统计或模拟季度主题。

- [当前 API 契约](docs/API_CONTRACT.md)：五字段明细、统计口径和 Topic mock。
- [Ubuntu 部署说明](docs/ubuntu-deployment.md)：依赖、查询表刷新、systemd、Nginx 和跨服务器配置。

`npm run preview` 只预览静态构建，不代理 API；使用 Nginx 或开发服务器联调。
仓库携带的 node_modules 是开发机产物，Ubuntu 上先执行 `npm ci` 安装 Linux 依赖。

## 联动分析工作台

主图下方的“分析范围”统一展示起止月份和所选方面，并支持独立清除方面筛选、返回上一个聚焦时间范围和重置分析。

方面分类树按语言机制、工程工具、性能效率、生态协作四组组织现有 13 个模型标签。父级只控制展开与收起，不新增模型分类，也不将多标签去重语料直接相加。搜索同时支持中文名称和 aspect 标识。

- 在分类树、画像扇区或雷达图标签选择方面，会同步维度下拉、月度时间线、去重语料统计卡与当前方面概览。画像仍保留所有方面作比较，选中项高亮。
- 月份点详情中的入口可打开该月所在季度的真实主题。
- 季度主题提供“时间线聚焦本季度”，把全局范围设为该季度；可通过范围栏返回原范围。
- 代表语料日期可反向定位到对应月份。
- 方面计数是提及次数；季度主题来自独立 BERTopic 聚类，没有方面映射，不会伪装成按方面过滤。主题按完整季度统计，遇到月度部分范围会提示口径。

## 后续修改与发布顺序

固定流程：本地修改和验证 → 提交并推送 GitHub → 服务器同步 GitHub 中的同一提交 → 检查线上页面与接口。不要先部署服务器、再补推 GitHub。个人 `.env.*.local`、依赖缓存和本地备份不参与提交。


## 主图与 02—03 联动

时间线是页面主图。滚轮、拖动和顶部年月选择器沿用同一个全局时间范围，不引入事件前后局部窗口。分类树与方面概览已并入 03“方面与主题追踪”，02 保留饼图与雷达图。

02 选择方面后，03 保持完整季度主题的统计口径，并通过真实 `sentiment-facts` 明细的 corpus_id 核对主题代表语料。命中的主题优先展示，可切换“仅看代表语料命中的主题”。代表语料同时展示已核对的方面标签。03 主题的“在 02 画像突出相关方面”会高亮这些真实方面，不把整个主题误认成固定方面分类。

关联查询限定为当前全局时间范围与所选季度的交集；最多读取 10 页、每页 1000 条，复用最近 8 个时间范围缓存。覆盖不完整或接口失败时显示说明，不凭关键词推断方面，不把未命中当作无关联。季度主题总量和占比分母不因代表语料筛选而改变。事件节点继续标为 mock；点击事件可定位其季度，不改动全局起止年月。

执行 `npm test` 可检查 ID 匹配、多标签合并、分页游标、查询上限与缓存行为。


### 自由组合方面与时间段主题

- 四项核心指标保留在主图上方。时间线的“组合方面”可打开 03 的多选分类树，支持逐项叠加、按组选择、全选和清空。主图按所选方面的标注次数计算组合评分；02 保留全部分类以便比较，并突出已选方面。
- 组合的语料量、正向量、负向量读取全部所选方面明细后按 corpus_id 去重；方面标注量按 corpus_id + aspect 去重。正负两项可能包含同一条语料。统计未完成或请求失败时显示“—”，不会拿方面汇总数冒充去重语料量。多选查询最多 3 路并发，单方面最多 100 页，达到上限时报错。
- 主题支持“按季度”和“按时间段”。后者跟随主图/顶部自由年月，按相交季度分组并按需加载。后端仅提供季度独立聚类，因此保留完整季度的数量、占比与关键词；不合并跨季度 topic_id，不声称对自由区间重新聚类。
- 多方面与主题的关联按代表语料命中任一所选方面判断，不根据关键词猜测分类。代表语料明细最多核对 10 页，覆盖不足时会明确提示。


### 变化探针与临时聚焦

时间线下方的“发现变化”开关会标出当前范围内评分环比变化幅度最大的 5 个月。只比较有数据的连续自然月，沿用当前方面组合；标记和月份按钮均可展开证据。少于 30 次方面标注时显示低样本提示。排序仅描述变化幅度，不是异常检验，也不证明与 Rust mock 事件存在因果关系。

证据区展示两个月的评分、样本量以及所选方面的正负标注数量差值。数量差值不当作对组合评分变化的贡献。原始语料只使用真实季度主题代表语料，再用 corpus_id、UTC 月份、方面和情感明细交叉核对；支持三类情感筛选、分批展开、GitHub 原文和具体主题跳转。代表语料不能代表当月全部讨论，明细核对上限 10,000 条，覆盖不完整时明确提示。切换分析范围/方面或刷新数据会清除旧证据，异步响应通过版本校验避免串月。

02 图表分类和 03 分类树支持鼠标经过或键盘聚焦临时预览，相关画像和已加载主题会突出。预览不修改顶部时间、方面组合或主图。触屏点击图表可先预览，再通过“只看此方面”或“加入当前组合/从组合移除”确认。03 反向选择主题仍保留原有真实代表语料关联逻辑。

饼图扇区与引导分类名均支持点击切换选中状态（键盘 Enter/空格同样生效），保留其他已选方面。初始为全部方面总览；点击一个方面直接单选。已有单选或组合时点击增减，取消最后一项恢复全部方面。饼图、分类树单项和预览按钮采用同一规则。分类详情弹窗已移除，选择后的数量、评分及正中负分布直接显示在 03 方面概览。


### AI 分析与改进建议（GLM-5.3）

页面流程为 01 选时间 → 02 选方面 → 03 核对主题与关键词 → 04 改进意见。03 下方的按钮只进入 04，不自动生成。04 默认依据整个选定时间区间与方面组合生成解读、改进方向、验证方式及证据引用。变化探针可单独把某个月的环比分析带入 04，并可返回区间分析。
本功能使用本仓库 `server/advice_service.py` 独立服务，不修改原后端结构、数据库及 `/api/v1/*` 接口；只新增 `/ai-advice/` 路径。
密钥保存在服务器 `/home/wyh/.config/developer-voice/ai.env` 的 `GLM_API_KEY`，不会写入前端或 GitHub。默认全站每日最多 20 次新生成（可配置），缓存结果可重复查看。
源码位置、调用流程、配置、部署和关闭方法详见 [AI 建议说明](docs/ai-advice.md)。

04 保留此前生成的意见，但时间或方面改变后会明确标记旧范围，需点击“生成当前范围意见”更新；不会将旧意见当作当前结果。全区间统计使用完整月序列；代表语料最多均匀抽取 12 个相交季度，每季度核对前 3,000 条明细，显示的样例不代表全部讨论。原后端与 `/api/v1/*` 接口保持不变。
